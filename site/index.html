Browser-side PDF export · open source

The invoice on your screen, as a proper PDF.

zedpdf takes an element from your page, such as an invoice, a quote or a monthly report, and writes a PDF of it right there in the browser. Text stays text, tables break between rows, and the file usually comes out smaller than the one Chrome's print dialog makes.

    03 File size

    Light enough to email.

    Fonts only carry the letters you used. Photos are stored at the size they'll be printed (300 dpi), not the size they were taken. A logo that appears on every page is stored once.

    DocumentMade withSize
    Two-page invoicelogo, photo, 28 rowszedpdf49 KB
    Chrome's print72 KB
    html2pdf.js1,048 KB
    1,000-row invoice49 pageszedpdf221 KB
    Chrome's print283 KB
    Nepali and Englishshaped words as imageszedpdf82 KB
    Chrome's print77 KB

    Where it loses. Pages in Nepali, Hindi or Arabic come out a little bigger than Chrome's print, because those words are stored as small images to get the letter shapes right. We'd rather say so than round it off.

    05 Using it

    One element. Every way out.

    Point it at an element, then decide what should happen: save it, print it, open it, show it in the page, share it or upload it. Plain HTML pages can do all of that with attributes alone, no script of your own.

    import { pdf } from 'zedpdf';

const invoice = pdf('#invoice', { format: 'A4', filename: 'INV-2026-0042' });

await invoice.download();             // save the file
await invoice.open();                 // show it in a new tab
await invoice.preview('#viewer');     // show it in your page
await invoice.print();                // the browser's print dialog
await invoice.share();                // phone share sheet, or a download

    06 What it covers

    Built for the pages businesses actually print.

    There's no screenshot involved. The browser lays your element out once, at the width of the paper. zedpdf reads where every word and box ended up, decides where pages should break, and writes those positions straight into the PDF. That's why columns don't wander from page to page and why the text can be copied.

    Handled

    • Tables with repeating headers, nested tables, merged cells
    • Rows longer than a page, split cleanly between lines
    • Your web fonts, bold and italic, currency signs
    • Logos with transparency, photos, SVG icons, canvas charts
    • Flex and grid layouts, two-column text, lists
    • Links you can click, form values, checkboxes
    • Chrome, Edge, Firefox and Safari's engine

    Not yet

    • Built-in shaping for Hindi, Nepali or Arabic (an image-based fallback works today)
    • WOFF2 font files (TTF, OTF and WOFF work)
    • CSS background images and gradients
    • Rotated or scaled elements, blur and other filters
    • Accessibility tags inside the PDF
    • Tables that only render the rows on screen
