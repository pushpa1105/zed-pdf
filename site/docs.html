Documentation

zedpdf

zedpdf turns an HTML element in your page into a real PDF, entirely in the browser. Typical uses are an invoice, quotation, purchase order, statement, report or dashboard. You pass the element and get back a PDF Blob that looks like the browser's own print.

The text in the PDF is real text, set in your own fonts, so people can select it, search it and copy it out. Pages break between table rows and lines rather than through them, and table headers repeat on each page. Files stay small because fonts only carry the letters used and photos are stored at print size.

It all happens in the browser tab. There is no server, no headless browser and nothing to install besides the package itself. When something on your page can't be reproduced, you get a warning naming the element and what to do about it, instead of a quietly wrong PDF.

In one line. pdf('#invoice').download() saves it; .print(), .open(), .preview(el), .share() and .file() do the other things you'd expect. On a plain HTML page, <button data-zedpdf="download" data-zedpdf-target="#invoice"> does the same with no script of your own.

Installation

With a package manager

terminal
npm install zedpdf      # or: pnpm add zedpdf / yarn add zedpdf
import { pdf, exportPdf, printElement, bindActions } from 'zedpdf';

The package is ESM-only and ships TypeScript types.

Plain HTML with a script tag (no npm, no build step)

Copy dist/zedpdf.global.js from the package into your site. The file is 37 KB gzipped. It exposes a global ZedPdf:

<script src="/js/zedpdf.global.js"></script>

<!-- that's all: these buttons work as they are -->
<button data-zedpdf="download" data-zedpdf-target="#invoice">Download PDF</button>
<button data-zedpdf="print" data-zedpdf-target="#invoice">Print</button>

<script>
  // or from your own code:
  ZedPdf.pdf('#invoice').open();
</script>

Plain HTML with an ES module

<script type="importmap">
  { "imports": { "zedpdf": "./node_modules/zedpdf/dist/zedpdf.js" } }
</script>
<script type="module">
  import { exportPdf, savePdf } from 'zedpdf';
</script>

From a CDN

The package is mirrored by public CDNs. Pin the exact version so an update never changes your output unexpectedly. Using a CDN is optional, because the library never loads anything from a CDN itself.

import { exportPdf } from 'https://cdn.jsdelivr.net/npm/zedpdf@{{VERSION}}/dist/zedpdf.js';
Serve over http(s). Browsers refuse ES modules from file://, and zedpdf reads your font and image files in order to embed them. Any local server works, for example npx serve ..

Browser requirements

zedpdf needs CompressionStream (Chrome/Edge 80+, Firefox 113+, Safari 16.4+), Range.getClientRects and document.fonts. It is tested in Chromium, Firefox and WebKit. See Supported HTML & CSS.

Quick start

Download button

import { pdf } from 'zedpdf';

downloadButton.addEventListener('click', () =>
  pdf('#invoice', {
    format: 'A4',  // 'A4' | 'Letter' | 'A3' | 'A5' | 'Legal' | { width, height }
    margin: '12mm',
    title: 'Invoice INV-2026-0042',
  }).download(),  // saves "Invoice-INV-2026-0042.pdf"
);

Prefer no JavaScript at all? See buttons without JavaScript.

Preview in the page

await pdf('#invoice').preview('#viewer');  // an iframe, or a container that gets one

Upload or email it

const body = new FormData();
body.append('file', await pdf('#invoice').file('invoice.pdf'));
await fetch('/api/invoices/42/pdf', { method: 'POST', body });

The lower-level function

exportPdf(element, options) is what pdf() uses underneath. It returns the same result object, with the same actions: (await exportPdf(el)).download().

Actions

Most apps want to do something with the PDF straight away: save it, print it, show it, send it. pdf() gives you a handle on an element with all of those as methods. Each call takes a fresh snapshot, so the PDF always matches what is on screen at that moment.

import { pdf } from 'zedpdf';

const invoice = pdf('#invoice', {  // an element or a CSS selector
  format: 'A4',
  margin: '12mm',
  title: 'Invoice INV-2026-0042',
  filename: 'INV-2026-0042',  // used by download/share/file; ".pdf" is added
});

await invoice.download();  // saves INV-2026-0042.pdf
await invoice.print();  // the browser's print dialog, just this element
await invoice.open();  // opens the PDF in a new tab
await invoice.preview('#viewer');  // shows it inside #viewer
await invoice.share();  // share sheet on phones; downloads elsewhere
const file = await invoice.file();  // a File, for uploads
const blob = await invoice.blob();  // the raw Blob
const result = await invoice.render();  // everything: blob, pageCount, warnings + actions
MethodWhat it does
download(name?)Saves the PDF through the browser's normal download. The name comes from name, else filename, else the title, else document.pdf.
print()Opens the native print dialog for just this element; resolves after it closes.
open()Opens a new tab immediately (so popup blockers allow it), then shows the PDF in it. If popups are blocked anyway, it downloads instead.
preview(where)where is an <iframe>, a container (an iframe is created inside it) or a selector. Calling it again replaces the PDF and releases the old one.
share(data?)Uses the system share sheet where the browser supports sharing files (most phones). Resolves to 'shared', 'cancelled' or 'downloaded' (the fallback).
file(name?) / blob()The PDF as a File (ready for FormData) or a Blob.
render()The full result: blob, pageCount, warnings, timings, plus every action below.

Every method also accepts per-call options, e.g. invoice.download('copy.pdf', { margin: '20mm' }).

Doing several things with one export

The result of render(), and of exportPdf(), carries the same actions, so you can export once and reuse the file:

const result = await pdf('#invoice').render();
result.preview('#viewer');  // show it
saveButton.onclick = () => result.download();
uploadButton.onclick = () => upload(result.file('invoice.pdf'));
// result.url() gives a stable object URL; call result.dispose() when you no longer need it.

Buttons without JavaScript

With the script-tag build, any element with data-zedpdf becomes a PDF button. Nothing else is needed:

<script src="zedpdf.global.js"></script>

<button data-zedpdf="download" data-zedpdf-target="#invoice" data-zedpdf-filename="INV-42">Download</button>
<button data-zedpdf="print"    data-zedpdf-target="#invoice" data-zedpdf-format="Letter">Print</button>
<button data-zedpdf="open"     data-zedpdf-target="#invoice">Open</button>
<button data-zedpdf="preview"  data-zedpdf-target="#invoice" data-zedpdf-preview="#viewer">Preview</button>
<button data-zedpdf="share"    data-zedpdf-target="#invoice" data-zedpdf-title="Invoice 42">Share</button>
AttributeMeaning
data-zedpdfdownload, print, open, preview or share
data-zedpdf-targetSelector of the element to export. Without it, the nearest ancestor with data-zedpdf-root is used.
data-zedpdf-previewWhere preview shows the PDF (default: [data-zedpdf-viewer])
data-zedpdf-filename, -titleFile name and document title
data-zedpdf-format, -orientation, -marginPage setup, e.g. Letter, landscape, 12mm
data-zedpdf-media, -css, -strict, -complex-scriptsThe matching options
data-zedpdf-optionsAny options as JSON, e.g. '{"maxImageDpi":200}'

While a button is working it is disabled and has aria-busy="true", which you can style ([aria-busy="true"] { cursor: progress }). When it finishes it fires a bubbling event:

document.addEventListener('zedpdf:done', (e) => {
  const { action, result } = e.detail;  // result.pageCount, result.warnings …
});
document.addEventListener('zedpdf:error', (e) => {
  console.warn(e.detail.action, e.detail.error.code);
});

The script-tag build binds buttons automatically. With the ES module, call bindActions() once (it returns a function that unbinds). To stop the script-tag build from binding, add data-zedpdf-manual to its <script> tag.

import { bindActions } from 'zedpdf';
const unbind = bindActions();  // or bindActions(someContainer)

Frameworks

zedpdf takes an ordinary HTMLElement, so any framework that gives you a DOM element works without a wrapper. Styles defined anywhere in the page are reproduced: Vue scoped styles, CSS modules, Tailwind, CSS-in-JS, and themes set on parent elements.

<script setup>
import { ref } from 'vue';
import { pdf } from 'zedpdf';

const invoice = ref(null);  // a component ref? use invoice.value.$el
const download = () => pdf(invoice.value, { format: 'A4', filename: 'invoice' }).download();
</script>

<template>
  <button @click="download">Download PDF</button>
  <div ref="invoice"><InvoiceDoc /></div>
</template>
import { useRef } from 'react';
import { pdf } from 'zedpdf';

export function InvoicePage() {
  const ref = useRef(null);
  const download = () => pdf(ref.current, { format: 'Letter', filename: 'invoice' }).download();
  return (
    <>
      <button onClick={download}>Download PDF</button>
      <article ref={ref}>…</article>
    </>
  );
}
import { Component, ElementRef, ViewChild } from '@angular/core';
import { pdf } from 'zedpdf';

@Component({
  selector: 'app-invoice',
  template: `<button (click)="download()">Download PDF</button>
             <article #invoice>…</article>`,
})
export class InvoiceComponent {
  @ViewChild('invoice') invoice!: ElementRef<HTMLElement>;
  download() {
    return pdf(this.invoice.nativeElement, { filename: 'invoice' }).download();
  }
}
<script>
  import { pdf } from 'zedpdf';
  let invoice;
  const download = () => pdf(invoice, { filename: 'invoice' }).download();
</script>

<button on:click={download}>Download PDF</button>
<article bind:this={invoice}>…</article>

The Vue 3 and React examples are installed and tested from the packed npm tarball. The Angular and Svelte snippets use the same API but are not separately tested.

Page size & margins

await pdf(el, { format: 'A4', orientation: 'portrait', margin: '10mm' }).download();  // defaults
await pdf(el, { format: 'Letter', orientation: 'landscape', margin: '0.5in' }).download();
await pdf(el, { format: { width: '210mm', height: '99mm' }, margin: 0 }).download();  // custom (e.g. a DL slip)
await pdf(el, { margin: { top: '20mm', right: '12mm', bottom: '20mm', left: '12mm' } }).download();

Lengths can be numbers (CSS px) or strings in mm, cm, in, pt, pc or px. The element is laid out at the page's printable width, which is the paper width minus the left and right margins, just like print. Responsive CSS (@media (max-width)) therefore applies exactly as it would when printing.

Headers, footers & page numbers

Pass HTML that is repeated on every page. Elements with the class pageNumber or totalPages receive the numbers. This is the same convention as Chromium's header templates.

await pdf(el, {
  header: { html: '<div style="font: 10px sans-serif; text-align: right">ACME Ltd · Confidential</div>' },
  footer: {
    html: `<div style="display:flex; justify-content:space-between; font:10px sans-serif; border-top:1px solid #ddd; padding-top:6px">
             <span>INV-2026-0042</span>
             <span>Page <span class="pageNumber"></span> of <span class="totalPages"></span></span>
           </div>`,
  },
}).download();

The header and footer sit inside the margins, and their height is taken from the content area. Your page's stylesheets and fonts apply to them too.

Styling the export

Your @media print rules apply

By default (media: 'print'), exportPdf uses your print stylesheet: @media print rules are applied and @media screen rules are switched off. Buttons, navigation and other screen-only chrome that you already hide when printing are hidden in the PDF too. Pass media: 'screen' to export the screen appearance instead.

Export-only CSS

Use css for rules that should only apply to the PDF. The export root also carries the class zedpdf-export.

await pdf(el, {
  css: `
    .no-pdf, .toolbar { display: none !important; }
    .invoice { box-shadow: none; }
    .totals { break-inside: avoid; }
  `,
}).download();

What gets copied

The element is cloned into a hidden frame together with every stylesheet in the page (including CSS-in-JS and adopted stylesheets), the attributes of <html> and <body>, and a lightweight copy of each parent element. Selectors such as .theme-dark .invoice, CSS variables, inherited fonts and colours therefore resolve exactly as on screen. Your live page, its scroll position and its state are never modified.

Tip. Scrollable areas inside the element are expanded so that all of their content is exported. Set expandScrollContainers: false to keep the clipped view.

Page breaks & tables

Pages break only between blocks, table rows and lines of text. Your CSS controls the choices:

CSSEffect
break-before: page / break-after: pageForce a new page (never creates a blank first or last page)
break-inside: avoidKeep a block (e.g. totals, signature, a card) together when it fits on a page
break-after: avoidKeep a heading with what follows (or pass keepHeadingsWithNext: true)
orphans / widowsMinimum lines of a paragraph at the bottom and top of a page (default 2)

How tables are handled

  • Header rows (<thead>) repeat on every page a table spans. Space is reserved for them first, and a header is never left alone at the bottom of a page. Turn this off with repeatTableHeader: false.
  • Rows stay whole when they fit on a page. A row that exactly fills the remaining space stays.
  • Rows taller than a page split between lines of text, each cell continuing independently. Amounts and images are painted once, and the next row starts after every cell has finished.
  • Footer rows (<tfoot>) such as invoice totals are drawn once, after the last row.
  • Columns never drift. Widths, alignment, backgrounds and borders are identical on every page.
  • Nested tables paginate inside their cell, with their own header repeated.
  • colspan is supported. rowspan groups are kept together when they fit on a page; a group taller than a page is split with a rowspan-split warning.
  • A header taller than a quarter of the page is not repeated, so that body rows still fit. You'll get a warning.

Content taller than a page

An image taller than a page is scaled down to fit by default. Set oversizedImage: 'slice' to split it across pages instead. Other content that cannot break, such as a very tall inline-block, is sliced, and you'll get a warning.

Fonts

To embed a font, zedpdf needs the font file. A CSS font-family name alone is not enough. It finds font files automatically from your @font-face rules (TTF, OTF or WOFF) and embeds only the characters used, with a Unicode map so that copy and paste works.

@font-face {
  font-family: 'Inter';
  src: url('/fonts/Inter-Regular.woff') format('woff');     /* TTF / OTF / WOFF are embeddable */
  font-weight: 400;
}

You can also hand zedpdf the bytes directly, for example when fonts are bundled or loaded with authentication:

await pdf(el, {
  fonts: [
    { family: 'Inter', weight: 400, src: '/fonts/Inter-Regular.ttf' },
    { family: 'Inter', weight: 700, src: await (await fetch('/fonts/Inter-Bold.ttf')).arrayBuffer() },
  ],
}).download();
  • System fonts (Arial, Segoe UI, Helvetica…) cannot be read by web pages. Text in them falls back to the built-in PDF fonts (Helvetica, Times or Courier), still at the exact measured positions, and you'll get a font-substituted warning. For a pixel match, use a web font.
  • WOFF2 files are not supported yet. Add a WOFF or TTF src alongside the WOFF2.
  • Missing characters are reported as missing-glyph. They are never silently replaced.

Images & file size

Images are embedded at the resolution they need for the size they are printed at, and no more:

  • maxImageDpi (default 300): a 4000×3000 photo shown as a 240 px thumbnail is downsampled to 750 px wide. Set false to keep originals.
  • JPEG files that are already small enough are embedded byte for byte, with no recompression. Photos that are downsampled are re-encoded at jpegQuality (default 0.85).
  • PNG keeps transparency. Logos and graphics stay lossless.
  • SVG, WebP, GIF and <canvas> are rasterized (SVG and canvas at rasterScale × size, 288 dpi by default).
  • The same image used many times, such as a logo on every page or an icon in every row, is stored once.

Fonts are subset to the glyphs used, and drawing instructions are deduplicated. A typical two-page invoice comes to about 50 KB, smaller than the browser's own print output.

Images behind authentication or another domain

zedpdf reads image bytes with fetch. Images on another domain need CORS headers. If your app already has the bytes, or needs to add an auth header, supply them yourself:

await pdf(el, {
  assetResolver: async (url, kind) => {  // kind: 'image' | 'font'
    if (url.startsWith('https://files.example.com/')) {
      const res = await fetch(url, { headers: { Authorization: `Bearer ${token}` } });
      return res.arrayBuffer();
    }
    return null;  // let zedpdf fetch it normally
  },
}).download();

An image that cannot be read produces an asset-unavailable warning naming the element and URL. The rest of the document is still exported.

Links, forms & charts

  • Links: text inside <a href> with an http(s):, mailto: or tel: URL becomes a clickable link in the PDF. In-page #anchor links are not linked yet.
  • Form controls: inputs, selects and textareas are drawn with their box and current value. Checkboxes and radio buttons are drawn as vector shapes in the browser's default style.
  • Charts: <canvas> charts (Chart.js, ECharts and similar) are captured at their pixel resolution. SVG charts are rasterized at high resolution.
  • Lists, details, pre, multi-column text: bullets and disclosure triangles are drawn as shapes. Closed details content stays hidden, whitespace in pre is preserved, and multi-column text keeps its reading order.
  • Generated content: text from ::before and ::after is exported. counter() values are not, and produce a warning.

Languages & complex scripts

Latin, Greek and Cyrillic text, plus symbols such as € £ ₹ − “ ”, work with any embedded font that contains them. Scripts that need OpenType shaping, such as Devanagari (Nepali, Hindi), Bengali, Arabic and Thai, are handled in one of two ways:

OptionLooksCopy / search
complexScriptFallback: 'none' (default)Unshaped glyphs (conjuncts not formed); warningCorrect
complexScriptFallback: 'raster'Shaped by the browser, drawn as a 288 dpi image per wordCorrect (invisible text layer)
printElement()Shaped natively by the print engineDepends on the browser
 
await pdf(el, { complexScriptFallback: 'raster' }).download();  // recommended for Nepali / Hindi / Arabic documents

Identical words, such as a repeated customer name, share one image, so the file stays small. Make sure the CSS font list includes a font for the script, for example font-family: 'Noto Sans', 'Noto Sans Devanagari', sans-serif.

Warnings & strict mode

Every export returns warnings, each one structured like this:

{
  code: 'asset-unavailable',
  severity: 'warning',  // 'info' | 'warning' | 'error'
  message: 'Image could not be loaded: https://…/logo.png',
  element: 'div.brand > img',  // where it happened
  remedy: 'Check the URL/CORS, or provide the bytes with options.assetResolver',
  count: 1,  // identical warnings are folded
}

info warnings describe deliberate choices, for example "SVG rasterized" or "image downsampled". warning means something visible may differ from the screen. If your use case cannot accept that, for example a legal document, turn on strict mode:

try {
  await pdf(el, { strict: true }).download();
} catch (e) {
  if (e.code === 'fidelity') console.table(e.warnings);  // nothing was exported
}

See all warning codes.

Cancellation & progress

const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

await pdf(el, {
  signal: controller.signal,
  onProgress: (stage, info) => console.log(stage, info),  // surface → measure → assets → paginate → render → done
}).download();

A cancelled export rejects with ZedPdfError code 'aborted'. The temporary hidden frame is always removed, whether the export succeeds, fails or is cancelled.

Native print

printElement() opens the browser's print dialog for just the element, not the whole page. The browser's own print engine lays it out, so @media print, @page and break-* apply natively. The user can print or choose Save as PDF.

import { printElement } from 'zedpdf';
await printElement(el, { format: 'A4', margin: '12mm', title: 'Invoice INV-2026-0042' });
// resolves after the dialog closes

Use exportPdf when you need the file in code, for a download button, preview or upload. Use printElement when the user wants a printer, or when a script needs native shaping without the raster fallback.

pdf() & bindActions()

pdf(target, options?) → PdfHandle

target is an HTMLElement or a CSS selector, resolved each time an action runs. options are the exportPdf options, plus applyPageRule for print(). The handle has download, print, open, preview, share, file, blob and render; see Actions.

The result object

exportPdf() and render() resolve to a PdfFile: { blob, pageCount, warnings, timings, filename } plus download(name?), open(), preview(where), share(data?), file(name?), url() and dispose().

bindActions(root = document) → unbind

Turns data-zedpdf elements inside root into PDF buttons and returns a function that removes the listener. The script-tag build calls it for you. Events: zedpdf:done and zedpdf:error, both bubbling, with detail.action and detail.result or detail.error.

exportPdf(element, options?)

Returns Promise<PdfFile>: { blob, pageCount, warnings, timings } plus the result actions.

Supported HTML & CSS

Supported

  • Block, flex, grid and multi-column layouts; floats; absolute positioning
  • Tables: thead, tfoot, captions, nested tables, colspan, rowspan
  • Backgrounds with alpha, borders (solid, dashed, dotted, double), rounded corners, outer shadows, overflow clipping, opacity
  • Text: web fonts, weights, italics, letter-spacing, text-transform, underline and strike, sub/sup, justification, <br>, pre
  • Images: PNG, JPEG, SVG, WebP, GIF, canvas, srcset, object-fit
  • Lists, details/summary, ::before/::after, links, forms
  • Vue scoped CSS, CSS modules, Tailwind, CSS variables, ancestor themes

Not yet

  • WOFF2 fonts
  • CSS background images and gradients
  • Rotate, scale and skew transforms; filters; blend modes; text-shadow
  • Tagged (accessible) PDF structure; in-page #anchor links
  • Shadow DOM content, <iframe> content
  • Virtualized lists and tables: only rows currently in the DOM can be exported

Troubleshooting

The PDF uses Helvetica instead of my font

zedpdf couldn't read the font file. Check the font-substituted warning. Typical causes: the font is a system font, only a WOFF2 file is provided, the font is on another domain without CORS, or the page was opened from file://.

An image is missing

Look for asset-unavailable. Images on another domain need CORS headers (Access-Control-Allow-Origin). Images behind a login can be supplied through assetResolver.

Something is cut off on the right

The layout is wider than the printable width (see horizontal-overflow). Use fluid widths (max-width: 100%), smaller margins or landscape. Wide tables can use table-layout: fixed plus overflow-wrap: anywhere.

A block breaks where I don't want it to

Add break-inside: avoid to it, or break-before: page to start it on a new page. Pass those through options.css if you don't want them on screen.

Only some rows of my table appear

Virtualized tables only keep visible rows in the DOM. Render all rows (for example in a hidden print view) before calling exportPdf.

Exports of very large documents are slow

On a laptop, 1,000 rows (49 pages) take about 1 s in Chromium and Firefox, and 2–3 s in WebKit. Show progress with onProgress and allow cancellation with signal.

The PDF shows things I hide when printing (or vice versa)

The default is media: 'print'. If your screen styles are what you want exported, pass media: 'screen'.

How it works

  1. Clone. The element is copied into an offscreen same-origin iframe at the printable width, with its stylesheets, parent context and generated content.
  2. Measure. Box and word positions are read with getBoundingClientRect and Range.getClientRects, one call per word. Nothing is laid out again.
  3. Paginate. A pure algorithm chooses breaks following CSS Fragmentation Level 3 and CSS Tables Level 3. Each page reuses the measured geometry, shifted, so columns cannot move.
  4. Write. A small PDF writer produces vector paths, Type0/CID fonts with ToUnicode, right-sized images, link annotations and a byte-accurate cross-reference table.

The result is checked against Chromium's print-to-PDF and opened by two independent PDF engines (MuPDF and pdf.js) in the project's test suite.
